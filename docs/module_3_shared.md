# 一、房源展示规则（业务不变）

## 1.1 可见范围

共享房源库展示系统内全部已开放联卖的房源。所有已注册的经纪人（包括门店老板）均可浏览。**共享房源库作为App底部Tab之一**，从工作台首页可直接切换进入。

**App版底部导航**：
```
┌────┬────┬────┬────┐
│工作台│房源库│消息│ 我的│
└────┴────┴────┴────┘
     ↑
  默认进入工作台，点击"房源库"切换到共享房源库
```

**Flutter技术实现**：`BottomNavigationBar` + `IndexedStack`（保持各Tab状态不丢失）。

## 1.2 各状态展示逻辑

| **状态** | **展示内容** | **操作权限** | **标签样式** |
|---|---|---|---|
| 即将上市 | 房源基本信息、照片 | 可收藏，不可申请带客 | 蓝色 Chip |
| 在售 | 房源全部信息、实拍照片 | 可申请带客、可收藏 | 无特殊标签 |
| 定金已付 | 房源信息 + 定金已付状态 | 仍可申请带客（backup）、可收藏 | 橙色 Chip |
| 成交进行中 | 房源信息 + 成交进行中状态 | 仅查看和收藏 | 灰色 Chip |
| 已售 | 房源信息 + 成交价 + 成交时间 | 仅查看和收藏 | 灰色水印（整卡变灰） |
| 待确认 | 房源信息 + 7天未更新提示 | 可申请带客、可收藏 | 黄色 Chip |
| 锁定（经纪人离职） | 房源信息 + 「经纪人已离职，待移交」标注 | 可查看、可收藏，不可申请带客 | 灰色 Chip |

> *已售房源公开展示成交价和成交时间，为所有经纪人提供真实成交参考数据。定金已付仍允许申请带客，因为定金阶段双方仍可能反悔。*

## 1.3 不展示的状态

撤牌、暂停挂牌、已下架的房源在共享房源库中不展示。

## 4.2 卡片Flutter实现

```dart
Card(
  elevation: 1,
  margin: EdgeInsets.symmetric(horizontal: 16, vertical: 8),
  child: InkWell(
    onTap: () => context.push('/house/${house.mlsId}'),
    child: Row(
      children: [
        // 左侧图片（CachedNetworkImage带占位符）
        Hero(  // Hero动画：详情页大图过渡
          tag: 'house-${house.mlsId}',
          child: CachedNetworkImage(
            imageUrl: house.coverPhoto,
            width: 120, height: 120,
            fit: BoxFit.cover,
            placeholder: (_, __) => ShimmerSkeleton(),  // 骨架屏
            errorWidget: (_, __, ___) => Icon(Icons.home),
          ),
        ),
        // 右侧信息
        Expanded(child: Padding(...)),
      ],
    ),
  ),
)
```

**关键技术点**：
- `CachedNetworkImage`：图片本地缓存，弱网场景关键
- `Hero`：点击进入详情页时大图平滑过渡动画
- `InkWell`：点击波纹反馈（Material Design）
- 骨架屏：加载中占位，提升感知性能

## 6.2 乐观更新（V7新增）

点击收藏按钮的用户体验：

```
用户点击收藏按钮
  ↓
1. 本地立即更新UI（心形变红+收藏数+1）
  ↓
2. 本地Hive写入收藏记录（乐观更新）
  ↓
3. 后端API调用（异步）
  ├─ 成功 → 本地记录标记 synced=true
  └─ 失败 → 本地记录标记 synced=false
         → 显示"收藏失败，点击重试"小提示
         → 恢复UI（心形变空）
```

**优势**：
- 用户感知瞬时响应
- 弱网/离线场景也能先本地记录，联网后补同步
- 防抖：1秒内重复点击视为一次操作

**技术实现**：Riverpod `FavoriteNotifier` + Hive 本地队列。

## 6.4 状态变化通知（App版渠道调整）

收藏夹内房源发生以下变化时通知经纪人：调价、撤牌、已售、即将上市转为在售、暂停挂牌、从暂停恢复在售、从成交进行中回退为在售、待确认。

**通知方式（App版）**：

| **事件** | **渠道** |
|---|---|
| 调价/撤牌/已售/暂停挂牌/恢复在售/回退在售 | 极光推送 + App内消息中心 |
| 待确认/即将上市转在售 | 仅消息中心 |
| **定金回退为在售**（V8第七轮继承） | 极光推送 + 消息中心 |
| **定金凭证虚假回滚**（V8第七轮继承） | 极光推送 + 消息中心 |
| **重新上架旧收藏清除**（V9继承） | 极光推送 + 消息中心 |

> *区分两种「恢复在售」场景的通知文案。「从暂停挂牌恢复」和「从成交进行中回退」是不同的原因——前者是房东重新方便看房了，后者是交易取消了。详见模块七。*

> *通知频率控制：同一房源同一事件类型24小时内最多通知一次。*

# 七、关注小区（V7 App版增强）

# 十一、数据导出（App版调整）

**App版交付方式**：

- 后台异步生成Excel

> *导出操作记入audit_log。*
> *App不直接下载大文件，避免移动端弱网下载失败、存储占用等问题。与模块一V8第十四节的导出策略一致。*
