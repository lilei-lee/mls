# 一、模块概述

本模块覆盖交易留痕的后半段——从带看完成到成交确认、合作奖金结算，以及争议举报和仲裁处理。本模块与模块四（带客协作）共同构成MLS系统的完整交易留痕链。

> *六个留痕节点分布：节点①（房源录入）在模块二，节点②③④（带客申请/审批/带看）在模块四，节点⑤⑥（成交确认/奖金结算）在本模块。*

> *门店老板以经纪人身份参与交易时，在本模块中与普通经纪人遵循完全相同的规则。门店老板身份不赋予任何交易特权。*

# 二、交易留痕全链路总览

| **节点** | **名称** | **记录内容** | **所属模块** |
|---|---|---|---|
| ① | 房源录入 | 录入时间、经纪人身份、房源信息、独家委托协议 | 模块二 |
| ② | 带客申请 | 申请时间、申请人、客户姓氏/性别/需求 | 模块四 |
| ③ | 申请响应 | 响应时间、同意/拒绝、联络动作记录 | 模块四 |
| ④ | 实际带看 | 带看时间、现场照片（含EXIF+GPS）、双方确认 | 模块四 |
| ⑤ | 成交确认 | 双方经纪人分别独立填价、成交价 | 本模块 |
| ⑥ | 奖金结算 | Listing Agent确认已付、Buyer's Agent确认已收 | 本模块 |

所有节点数据一旦提交不可篡改，只能追加。完整时间线链条是争议裁判的核心依据。

# 三、成交确认（交易留痕节点⑤）

## 3.1 发起方

所有成交都由 **Buyer's Agent发起** 成交确认。LA自促成交时，LA以BA身份发起（详见3.5节）。不存在"无BA的成交"——所有成交必须有完整带看记录。

**发起前提条件**：

| **条件** | **说明** |
|---|---|
| BA有该房源已完成的带看记录 | 保证带看留痕 |
| 房源状态为「定金已付」或「成交进行中」 | 房源必须已进入交易阶段。在售状态拦截，提示"请先联系Listing Agent标记定金已付或直接签约后再发起成交确认"。无定金交易由LA标记"无定金直接签约"跳到成交进行中（详见模块二V11 §5.1） |

> *增加定金已付作为成交确认的门槛。定金标记需LA上传凭证，确保交易真实性。防止BA在没有任何交易实质进展的情况下发起虚假成交确认。自促成交场景中，LA先标记定金已付（自己操作），然后以BA身份发起成交确认。*

| **成交类型** | **发起方** | **确认方** | **说明** |
|---|---|---|---|
| 联卖成交 | Buyer's Agent | Listing Agent（独立填价比对） | BA关联自己的带看记录，避免关联错误 |
| LA自促成交 | LA以BA身份发起 | LA以LA身份确认（独立填价，形式化验证） | 系统检测LA=BA，自动通过审批和带看确认（详见3.5） |

## 3.1b BA未发起的催促与LA回退

| **时间节点** | **系统动作** |
|---|---|
| 成交实际发生后BA 7天未发起 | LA可发起催促通知，系统向BA推送提醒 |
| 成交实际发生后BA 14天未发起 | LA可作为备选发起方自行发起成交确认（此时回退到LA选择关联记录、BA确认时独立填成交价比对的模式） |

> *催促机制由LA在App内手动触发（点击"催促BA发起成交确认"），不是系统自动判断。LA回退发起时，双方独立填价机制对称——LA发起填价，BA确认时独立填价，一致才通过。BA收到后7天内未操作，系统自动视为确认（使用LA填写的成交价）。超时前24小时提醒BA。*

## 3.1c 同一房源单一待确认控制

同一房源在同一时间只能有一个待确认的成交记录。第二个BA尝试发起时被拦截，提示"该房源已有待确认的成交记录，请等待处理完成后再试"。如果当前待确认的成交被驳回或撤回后，其他BA可以重新发起。

**驳回超限冻结**：同一BA对同一房源的成交确认被 **LA手动驳回** 超过2次后，系统自动冻结该BA对该房源的成交确认 **发起** 权限。冻结后BA尝试发起时被拦截，提示"您对该房源的成交确认权限已冻结（连续驳回超过2次），请通过争议举报解决"。冻结记录进入audit_log，后台可见。

- **价格不一致的系统自动驳回不计入此计数**——价格不一致是双方协调问题，不代表LA对BA发起行为的否定
- **冻结只阻止BA发起，不阻止BA在LA回退发起场景中作为确认方操作**（独立填价）——LA回退发起本身意味着LA承认BA是成交人，BA的确认权不应被剥夺

**App版冻结提示UI**：

```
┌─────────────────────────────────────┐
│  ⚠ 无法发起成交确认                 │
├─────────────────────────────────────┤
│  您对房源【XXX】的成交确认发起权限   │
│  已被冻结（连续驳回超过2次）         │
│                                     │
│  建议您通过争议举报解决此问题：      │
│  [发起争议举报]                      │
│                                     │
│  或联系Listing Agent了解驳回原因：   │
│  [📞 拨号] [💬 发起微信沟通]        │
└─────────────────────────────────────┘
```

> *冻结解除条件：争议处理完毕后（无论BA胜诉或败诉），冻结自动解除，驳回计数归零。冻结是"强制走仲裁"的临时措施，不是永久惩罚。如果BA恶意举报，仲裁会给BA独立处罚。*

## 3.1d BA撤回成交确认

BA发起成交确认后、LA操作前（未确认也未驳回），BA可以主动撤回。

| **规则** | **说明** |
|---|---|
| 撤回条件 | LA尚未操作（未确认、未驳回、未超时自动生效） |
| 撤回后效果 | 该条成交确认作废，BA可以修改后重新发起 |
| 拦截解除 | 撤回后"同一房源单一待确认"拦截解除，系统通知被拦截的BA（如有） |
| 留痕 | 撤回操作记入audit_log |

**App版撤回UI**：成交确认详情页顶部展示倒计时"LA响应剩余X天Y小时"。底部"撤回成交确认"按钮（红色outline），点击弹出 `AlertDialog` 二次确认。

## 3.2b 成交价双方独立验证

LA确认成交时，系统要求LA **独立填写成交价**（LA看不到BA填的价格）。系统比对两个价格：

| **比对结果** | **处理方式** |
|---|---|
| 两个价格一致 | 成交确认通过，成交价生效 |
| 两个价格不一致 | 系统自动驳回，提示双方核实成交价。BA可修改后重新提交。 |

> *双方独立填价是成交数据保真的核心机制。任何一方都无法单独篡改成交价。如果反复不一致（驳回超过2次），系统建议通过争议举报解决。*

## 3.3 关联带客记录的规则

一套房源可能有多组Buyer's Agent带过客、同一个客户也可能被多个经纪人带看过，但成交确认只能关联 **一条** 带客记录——即促成本次成交的那一组Buyer's Agent和客户。

选择逻辑：Buyer's Agent从自己在该房源的「已完成带看确认」记录中选择关联对象。如果BA只有一条带看记录，系统自动关联。如果BA对同一房源多次带看不同客户，需选择本次成交对应的那一条。

不存在分奖金：合作奖金只付给被关联的那一位Buyer's Agent。其他曾经带看但未促成成交的Buyer's Agent不参与奖金分配。

> *MLS的合作奖金是对"促成成交的Buyer's Agent"的激励，不是对"所有带看过的经纪人"的普惠。谁的客户最终买了房，奖金就归谁。这与美国MLS的Commission Split逻辑一致——只有procuring cause（促成成交的直接原因）才获得买方佣金。*

## 3.4 Listing Agent确认（App版推送动作按钮）

Buyer's Agent提交后，Listing Agent收到通知，在App内操作。LA需要 **独立填写成交价**（见3.2b），然后确认或驳回。

| **操作** | **说明** |
|---|---|
| 确认（价格一致） | 成交记录正式生效。房源状态自动变为「已售」，成交价和成交时间在共享库公开展示。触发：奖金结算单自动生成、未关联BA通知。 |
| 驳回 | 需说明理由。驳回后Buyer's Agent可修改后重新提交。驳回通知中引导BA："可联系对方了解具体情况，或通过App发起争议举报"。驳回超过2次后，系统自动冻结该BA对该房源的成交确认发起权限，必须通过争议举报解锁（详见3.1c）。 |
| 价格不一致 | 系统自动驳回，双方核实后BA重新提交。 |
| 超时 | LA收到后7天内未操作，系统自动视为确认（使用BA填写的成交价）。触发所有后续流程：奖金结算单自动生成、未关联BA通知、房源状态变已售。 |

> *超时自动生效使用BA填写的价格。因为LA有7天时间+超时前24小时提醒，选择不操作视为默认同意BA填写的价格。超时自动生效后系统自动提醒后台人工介入核实成交价。*

## 3.4a 成交价修正申请

成交确认生效后 **30天内**，双方任一方可以发起"成交价修正申请"：

| **规则** | **说明** |
|---|---|
| 发起条件 | 成交确认生效后30天内，双方任一方可发起 |
| 修正流程 | 发起方填写修正后的成交价 → 另一方独立填写修正后的成交价 → 一致则修正生效 |
| 不一致 | 系统驳回，建议通过争议举报解决 |
| 超过30天 | 只能通过争议举报申请修正（90天举报时效内） |
| 留痕 | 修正前后的成交价都记入audit_log和transactions历史 |
| 通知范围 | 修正生效后通知双方+后台+已收到原成交通知的未关联BA |

> *典型场景：超时自动生效后LA发现BA填写的成交价有误，或双方确认后发现价格填错了。30天修正窗口提供低成本的纠错通道，不需要走完整的争议举报流程。*

## 3.4b 后台代确认

任何一方在成交确认流程中被暂停/踢出导致流程卡住，另一方可申请后台代为完成确认操作。后台代确认等同于正常确认，触发所有后续流程（奖金结算单生成、未关联BA通知、房源状态变已售）。代确认操作记入audit_log。

**自促成交例外**：LA自促成交（LA=BA）中，被暂停/踢出时不存在"另一方"可以申请。此场景下后台可直接代为确认，无需另一方申请触发。后台在"待代确认的成交"列表中可看到自促成交的卡住记录，直接操作。

## 3.4c 成交完成后通知未关联的Buyer's Agent

成交确认双方通过后（含超时自动生效、后台代确认），系统自动向该房源所有「已完成带看确认」但未被本次成交关联的Buyer's Agent发送通知。通知内容包含房源成交事实和成交价，并提示如有争议可在90天内举报（详见模块七）。

**App版通知渠道**：极光推送 + 服务号（如绑定） + 消息中心。通知内置"发起争议"深度链接按钮，点击直达争议举报页面预填该房源信息。

## 3.5 LA自促成交

所有成交必须有完整的带看记录。LA自己找到买家时，以LA+BA双重身份走完整流程：

| **步骤** | **操作** | **说明** |
|---|---|---|
| 1 | LA以BA身份发起带客申请 | 填写客户姓氏/性别/需求（同正常申请） |
| 2 | 系统检测LA=BA，自动通过审批 | 跳过匿名机制和等待环节 |
| 3 | LA以BA身份提交带看记录 | 上传带看照片（必填，实时相机拍摄），填写带看时间 |
| 4 | 系统检测LA=BA，自动确认带看 | 跳过LA确认带看的等待环节 |
| 5 | LA标记房源进入交易阶段 | 常规：标记「定金已付」并上传定金凭证。无定金交易：标记"无定金直接签约"并上传购房合同照片（详见模块二V11 §5.1） |
| 6 | LA以BA身份发起成交确认 | 填写成交价、成交日期等。房源必须处于定金已付/成交进行中 |
| 7 | LA以LA身份确认成交 | 独立填写成交价（自促场景下两次填价应一致），确认后生效 |

> *LA实际只需操作4步：填客户信息 → 上传带看照片 → 标记定金已付并上传凭证 → 发起+确认成交。自促成交与正常成交的路径规则完全一致，不存在任何豁免。7天有效期同样生效——自动通过审批后7天内需提交带看记录。*

> *自促成交的双方独立填价退化为形式化流程——同一人填两次相同价格无验证价值。自促成交的价格保真依赖后台巡检+事后惩罚（虚报成交价按最高等级处罚）。*

## 3.6 撤牌与成交的区别

| **场景** | **操作** | **数据公开** |
|---|---|---|
| 通过平台联卖成交 | 走成交确认流程（BA发起）→ 状态变为「已售」 | 成交价、成交时间公开展示 |
| Listing Agent自己促成成交 | LA以双重身份走完整流程 → 状态变为「已售」 | 成交价、成交时间公开展示 |
| 通过其他渠道成交（非平台） | 标记「撤牌」→ 选择原因「其他渠道成交」 | 不展示成交价，不计入平台成交统计 |
| 房东不卖了 | 标记「撤牌」→ 选择原因「房东不卖」 | 不展示 |

# 四、合作奖金结算（交易留痕节点⑥）

## 4.1 适用条件

仅当房源设置了合作奖金（奖金金额 > 0）且成交通过平台联卖达成（有关联的带客记录）时，才进入奖金结算流程。无奖金或无联卖关系的成交，此环节跳过。

## 4.2 结算流程

| **步骤** | **操作方** | **动作** | **说明** |
|---|---|---|---|
| 1 | 系统 | 自动生成结算单 | 成交确认通过后，系统根据房源**当前**设定的奖金金额自动生成结算单 |
| 2 | Listing Agent | 确认「奖金已付」 | 线下完成支付后，在App内点击确认 |
| 3 | Buyer's Agent | 确认「奖金已收」 | 收到通知后在App内确认 |
| 4 | 系统 | 结算完成 | 双方确认后，结算单状态变为「已结清」 |

**App版结算单UI**：

```
┌─────────────────────────────────────┐
│ ← 合作奖金结算                       │
├─────────────────────────────────────┤
│ 房源：北方明珠 3栋2单元602           │
│ 成交价：85万 · 成交日期：2026-04-20  │
│ Listing Agent：李明                  │
│ Buyer's Agent：王芳（您）            │
├─────────────────────────────────────┤
│ 合作奖金                             │
│ ¥ 2,000                              │
│ （该金额锁定为BA提交成交确认时的     │
│  奖金设定值，不受后续调整影响）      │
├─────────────────────────────────────┤
│ 结算进度                             │
│ ✔ Listing Agent已确认已付（4-21）   │
│ ○ 等待您确认已收                     │
├─────────────────────────────────────┤
│         [确认已收]                   │
└─────────────────────────────────────┘
```

## 4.2b 结算奖金金额取值规则

**结算单奖金金额 = BA提交成交确认时房源的当前奖金设定值。**"成交确认时"明确指BA提交的时刻（非LA确认时刻）。BA提交后奖金的任何变动不影响该笔结算。bonus_history保留完整的奖金变更历史供争议时参考。

> *典型场景：BA在奖金2000元时获批带客，期间发生归属变更，新归属人将奖金设为500元。BA最终促成成交并提交成交确认时奖金为500元，结算金额为500元。BA如果对此有异议可发起争议，仲裁委员会会参考bonus_history做裁判。*

## 4.3 结算超时提醒

成交确认通过后，如果7天内Listing Agent未确认奖金已付，系统提醒Listing Agent（极光推送+消息中心）。14天仍未确认，系统同时提醒双方。不自动处理，但超时记录可作为争议依据。

## 4.4 奖金金额争议

如果Buyer's Agent对结算单上的奖金金额有异议（与房源页面当时承诺的不一致），可以直接发起争议单。系统会调取该房源的奖金设置历史记录（bonus_history）作为裁判依据。

## 4.5 经纪人被踢出时的结算处理

经纪人被四级永久踢出时，如有未完成的奖金结算单，处理规则如下：

| **场景** | **处理方式** |
|---|---|
| 被踢出者是Listing Agent，尚未确认已付 | 结算单标记为「需人工介入」，后台主动联系被踢出者或房东跟进支付 |
| 被踢出者是Buyer's Agent，尚未确认已收 | 结算单标记为「需人工介入」，后台联系被踢出者确认是否已收到 |
| 对方可就此发起争议 | 被踢出者无法登录不影响另一方的举报权利，后台直接受理 |

> *平台不介入实际转账，只记录「已付」「已收」的双方确认。奖金的线下支付方式由经纪人自行决定。平台的角色是留痕和争议裁判。*

# 五、佣金相关说明

经纪人各自向各自的委托方收取服务费，费用标准和金额由经纪人与委托方自行约定。平台不记录佣金金额，不介入佣金结算，不做佣金相关的任何仲裁。

平台唯一涉及的费用是合作奖金——这是Listing Agent从自己的中介费收入中拿出的一部分，用于激励促成交易的Buyer's Agent。中介费由房东支付给LA，奖金由LA自愿设定和分配，平台不介入资金流向。

# 六、争议举报（V10 App版UI增强）

## 6.1 举报权利

仅交易双方（Listing Agent和Buyer's Agent）有权就该笔交易发起争议举报。非交易相关方无举报权。被踢出的经纪人无法登录，但另一方仍可发起举报，后台直接受理。

**争议一旦受理，独立于双方账号状态继续审理。** 即使举报方或被举报方在仲裁过程中被暂停/踢出，已受理的争议继续走完流程。暂停期间的当事人可以登录操作交易进行中的项目（含争议答辩）。

## 6.2 可举报的争议类型

| **争议类型** | **说明** | **典型场景** |
|---|---|---|
| 卖方飞单 | Listing Agent绕过Buyer's Agent，直接与其带来的客户成交 | 平台有带看记录，但成交不走平台流程，Buyer's Agent未获得应得的合作奖金 |
| 买方飞单 | Buyer's Agent绕过Listing Agent，直接联系房东促成交易 | 平台有带看记录，但成交绕过Listing Agent |
| 奖金未支付 | 成交已确认，但Listing Agent未支付承诺的合作奖金 | 结算单长期未完成，或Listing Agent声称已付但Buyer's Agent否认 |
| 奖金金额不符 | 实际支付的奖金金额与房源页面承诺的不一致 | Buyer's Agent收到的金额低于系统记录的承诺金额 |
| 虚假成交信息 | 成交确认中的价格或其他信息不真实 | 另一方发现申报的成交价与实际签约价不符 |

# 七、仲裁机制

## 7.1 仲裁委员会

| **事项** | **说明** |
|---|---|
| 组成 | 种子期：由平台运营方（磊）担任仲裁员。规模期：由3-5名资深经纪人组成，平台运营方担任主席。 |
| 回避制度 | 与争议任一方有直接利益关系的仲裁员必须回避 |
| 裁决效力 | 仲裁裁决为最终裁决，双方在加入平台时即同意接受仲裁约束 |

## 7.2 仲裁流程

| **步骤** | **动作** | **时限** | **说明** |
|---|---|---|---|
| 1 | 受理 | 收到举报后24小时内 | 系统通知被举报方（极光+服务号+消息中心），同时冻结相关结算单（如有） |
| 2 | 被举报方答辩 | 收到通知后7天内 | 被举报方提交答辩意见和证据 |
| 3 | 调取证据 | 答辩期结束后 | 仲裁委员会调取完整交易留痕时间线 |
| 4 | 审理 | 调取证据后7天内 | 仲裁委员会审理全部证据，必要时可要求双方补充材料 |
| 5 | 裁决 | 审理完成后3天内 | 出具书面裁决，包含事实认定、违规判定、处罚决定 |
| 6 | 执行 | 裁决后立即执行 | 系统自动执行处罚（功能限制/暂停/踢出） |

# 八、处罚体系

> *本节是全系统统一的处罚标准。模块一V8的处罚部分引用本节，不独立定义。*

## 8.1 处罚等级

| **等级** | **名称** | **适用情形** | **处罚内容** |
|---|---|---|---|
| 一级 | 警告 | 首次轻微违规 | 后台记录警告，通知当事人。其他经纪人不可见。 |
| 二级 | 公示 + 功能限制 | 首次严重违规或累计两次轻微违规 | 经纪人主页标注「有违规记录」（所有人可见）+ 30天功能限制 |
| 三级 | 暂停使用 | 二次严重违规或累计三次以上轻微违规 | 暂停MLS使用权30-90天。**可登录但仅能操作进行中的交易。** 房源保留标注「经纪人已暂停」。 |
| 四级 | 永久踢出 | 三次以上严重违规或单次特别恶劣行为 | 永久终止使用权。所有房源自动下架。未完成结算单标记「需人工介入」。被踢出者不可重新注册。 |

## 8.2 功能限制细则

| **违规类型** | **功能限制内容** | **限制时长** |
|---|---|---|
| 卖方飞单 | 新房源30天内不进入共享库（仅自己可见） | 30天 |
| 买方飞单 | 30天内不能发起新的带客申请 | 30天 |
| 奖金未支付 | 新房源不进入共享库，直至完成支付 | 直至结清 |
| 虚假成交价 | 直接进入二级处罚（公示） | 30天 + 公示 |
| 照片/信息不规范 | 房源下架，完善后可重新上架 | 直至完善 |
| 虚假标记定金 | 直接进入二级处罚（公示），情节严重进三级 | 30天 + 公示 |

## 8.3 暂停期间的规则

经纪人被暂停期间：**可以登录App，但仅能操作交易进行中的项目**。门店老板的「门店管理」入口不受影响。

| **暂停期间可做** | **暂停期间禁止** |
|---|---|
| 确认/驳回待确认的成交记录（作为LA） | 录入新房源 |
| 发起成交确认（作为BA，前提是已有完成的带看记录） | 发起新的带客申请 |
| 提交带看记录（已通过带客申请的下一步） | 审批新的带客申请 |
| 确认奖金结算（已付/已收） | 浏览共享房源库 |
| 确认/驳回待确认的带看记录（作为LA） | 编辑房源信息 |
| 提交争议答辩/补充材料 | 设置开放看房日 |
| 发起争议举报 | 设置关注小区/收藏房源 |

> *暂停期间BA可以发起成交确认和提交带看记录——前提是基于已有的、暂停前已通过的带客申请。这些操作属于"完成进行中的交易"，不是"发起新业务"。*

已有房源保留在系统中但标注「经纪人已暂停」，其他经纪人可见此标注但无法发起带客申请。合作奖金结算如有未完成的，冻结期间不计入超时。

**暂停期间未完成交易的详细处理规则详见模块一V8第10.1节。**

**App版暂停态UI**：登录后工作台顶部展示红色横幅"您的账号已暂停使用（X天后恢复），仅可操作进行中的交易。点击了解详情"。被禁用的入口全部置灰+Tooltip说明。

## 8.4 永久踢出的规则

经纪人被永久踢出时：所有房源自动下架；未完成的交易进入保护性处理——门店经纪人的未完成交易转给门店老板代为处理，独立经纪人/门店老板的未完成交易标记「需人工介入」，后台可代为完成成交确认操作；未完成的奖金结算单标记为「需人工介入」，后台主动跟进确保结算有最终结论；该经纪人的历史数据永久保留在系统中，不删除；被踢出者不可重新注册。

**App版踢出体验**：登录接口返回403+特定error_code。App展示"账号已被永久禁用"页面，提供"联系平台"按钮（邮箱+客服电话）。生物识别凭据自动清除，refresh_token失效。

## 8.5 违规记录的时效

轻微违规记录在24个月后自动清除。严重违规记录永久保留。公示标签在处罚执行完毕后12个月自动移除。

# 九、飞单的认定标准

## 9.1 卖方飞单的认定

同时满足以下条件：
1. 平台内存在带看确认记录
2. 成交买方与带看客户为同一人
3. Listing Agent未通过平台提交成交确认或未关联该Buyer's Agent
4. Buyer's Agent未获得承诺的合作奖金

## 9.2 买方飞单的认定

同时满足以下条件：
1. 平台内存在带看确认记录
2. 成交买方经纪人不是平台内Buyer's Agent或买方直接与房东成交
3. 有证据表明Buyer's Agent引导客户绕过Listing Agent

# 十、审计日志（audit_log）

## 10.1 设计原则

audit_log是MLS系统的底层基础设施，记录所有关键操作。数据只追加不修改不删除，是争议裁判的终极依据。

# 十三、并发控制技术方案

| **并发场景** | **解决方案** | **技术手段** |
|---|---|---|
| 两个BA同时发起成交确认 | partial unique index | `transactions`集合对`{house_id, status: "待确认"}`建partial unique index，第二个插入自动失败 |
| BA发起成交确认 + LA同时撤牌/暂停 | 待确认成交锁定状态变更 | LA操作撤牌/暂停时检查是否有待确认的transaction，有则拒绝并提示先驳回 |
| 7天超时自动生效 + LA最后一秒驳回 | 乐观锁 | 定时任务和手动驳回都用`findOneAndUpdate({status: "待确认"})`，先到先执行 |
| BA撤回 + LA同时确认 | 乐观锁 | 撤回和确认都检查`{status: "待确认"}`，只有一个能成功 |
| BA驳回超限冻结 | 计数检查 | BA发起成交确认时检查该BA对该house_id的历史驳回次数，≥2则拒绝 |
| LA回退发起BA超时 + BA最后一秒确认 | 乐观锁 | 与LA超时机制对称，定时任务和手动操作都检查`{status: "待BA确认"}` |
