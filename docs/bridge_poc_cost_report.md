## 6. 成本优化建议

| 优化项 | 预估效果 |
|---|---|
| 持久 session（去掉 `--no-session-persistence`，用 `--session-id` + `--resume`） | 复用系统提示词缓存，单次 input 从 33K tokens 降到 ~1K，**成本降低 50%+** |
| 小工单用 flash 模型 | `ANTHROPIC_DEFAULT_HAIKU_MODEL=deepseek-v4-flash`，单次 ~$0.002 |
| 工单路由规则 | 简单 reads 用 flash，复杂推理用 pro |
| 工单频率控制 | bridge 可限制 1-2 次/分钟，进一步压低成本 |

---

## 风险评估

| 风险 | 等级 | 说明 |
|---|---|---|
| 账单爆炸 | 🟢 低 | DeepSeek API 定价极低（$0.15-0.25/次），1 周 40h 高频也仅 $400-1200 |
| Rate limit | 🟢 低 | 实测 10 次/50s 全通过，bridge 频率（1 次/min）远低于实测压力 |
| 非交互式封禁 | 🟢 无风险 | DeepSeek 不区分调用模式，API key 即通行 |
| 模型不稳定 | 🟡 中 | DeepSeek 是第三方兼容端点，高峰期可能出现队列延迟 |

---

## 结论

**Bridge 自跑模式财务可行。** 1 周 40 小时连续自跑的预估成本约 $400-1200（取决于工单复杂度），不会导致月底账单爆炸。DeepSeek 端点无额外非交互式限制，实测 10 连发全部成功。

**建议实施时加**：
- 每个工单记录 cost → 月底汇总
- `--max-budget-usd` 设日/周上限防 runaway
- 简单工单走 flash 模型省成本
