**修法**:
1. VS Code 打开 `app/mls_app/lib/screens/collaboration_list_screen.dart`
2. Ctrl+F 搜 `/settlement/`(单数)
3. 改成 `/settlements/`(复数)
4. 顺手 Ctrl+F 搜 `/transaction/` 和 `/showing/`,核对单复数(可能也错了)
   - 正确路由参考(在 `app_router.dart` 里):
     - `/transactions/{id}` (复数,Day 7)
     - `/showings/{id}` (复数,Day 6)
     - `/settlements/{id}` (复数,Day 8)
     - `/showing-request/{id}` ⚠️ 注意是单数 + 中划线(Day 4 命名)
5. 保存,大 R 重启,真机点 4 种状态的卡都进得去就过

**预计**:5 分钟。Day 16 开工头一件事。

## 八、关键决策与协作约定(Day 10-15 累积)

### Day 9 晚定的(V2 IA 重构核心)

- **产品定位**:独立经纪人工作台 = 联卖 + 轻客户管理 + 财务结算
- **产品哲学**:信任演化原则 —— 机制服务于信任的演化,而不是反过来
- **4 条 IA 设计原则**:
  - 一标签不必一入口
  - 卡片可作待办提醒
  - 对象中心 > 动作中心
  - 轻管理优于重管理
- **匿名机制**:种子期保留 + 申请解密;长期开放(成熟期匿名可选;繁荣期实名为主)

### Day 10 定的(数据模型)

- 字段名铁律:showing_requests 集合用 `buyer_agent_id` / `listing_agent_id`,**其他集合**用 `ba_agent_id` / `la_agent_id`
- 客户管理是**轻管理**:基本信息 + 备忘 + 简单跟进,不做 CRM 重功能
- 术语铁律:"memo / 备忘 / 跟进记录"统一为 **"跟进记录"**(UI)

### Day 11+ 定的(开发节奏)

- **常规 commit 前缀**:`feat(DayN): ` / `fix(DayN): ` / `refactor(DayN): `
- **大 R 重启 vs 小 r 热重载**:加了 import / 改了 Widget tree / 加了方法 → 大 R;1 行简单改 → 小 r
- **VS Code 整替节奏**:Ctrl+A 等 1 秒 → Delete 等 1 秒 → Ctrl+V 等 1 秒 → Ctrl+End 验证 → Ctrl+S
- **粘贴新文件**:Ctrl+P 找文件夹 → New File → 直接 Ctrl+V → Ctrl+S(不用先 Ctrl+A)

### Day 14 末定的(产品规则)

- **1 客户 + 1 房 = 1 协作**(同房同客户只 1 条申请,但 1 申请 → N 带看,即 "申请 1:N 带看")

### Day 15 定的(1:N 带看实现细节)

- **prior_request 选择**:同房 + 同 BA + status in (approved, auto_approved) 时,取 `created_at` **最早**的一条作为协作锚点(与迁移脚本"保留最早条"一致)
- **客户信息源**:1:N 模式下"再次带看"不允许换客户,客户信息从 prior_request 取
- **归并不删**:被归并的 showing_request 不删,改 `status=merged_into_prior` + 加 `merged_into_request_id` 字段(留痕)
- **showings reparent**:归并时被合并条下挂的 showings 改写 `showing_request_id` 指到保留条,加 `original_request_id` + `reparented_at_day15` 字段
- **timeline 过滤**:`get_customer_timeline` 加 `status: {"$ne": "merged_into_prior"}`,免得客户时间线显示残骸申请
- **showing_count 字段**:协作卡片返 `showing_count: int`,前端忽略不影响(给"X 次带看"角标留口)

## 十三、Day 15 关键经验(避免重复踩)

### 经验 1:整替大文件时,新方法位置错了直接整替全文最稳

Day 15 末粘贴 `_showMyMenu` 时,误把方法贴到 `_TodoCard` 子组件类里(子组件不知道 `_myName` 是谁)。修法是直接重新整替整个 `home_screen.dart` 而不是局部移动。**经验**:精确移动方法位置容易出错,与其找空地,不如索性整替全文。

### 经验 2:Bug 暴露要等到真点

协作卡跳 404 这个 bug Day 13 就埋了,Day 15 末第一次真点才暴露。**经验**:验收清单里要包含"每张卡都至少点一次进详情"。

### 经验 3:迁移脚本 dry-run 是命根子

`migrate_collab_1n.py` 默认 dry-run,只在加 `--apply` 时真改;真改前自动 `$out` 备份。这套防御层在 Day 15 没出事但价值清楚——如果 dry-run 输出有意外组,你随时可以停下来排查,而不是数据已经被改坏。**经验**:任何写库脚本永远先 dry-run。
