## 任务详情

### 🔴 任务 0：内部系统性测试 V1（Day 17 头号大事）
- **背景**：V2 还未完善到展示给真实经纪人的程度。CLAUDE.md V1.1 第十五节明确：不做种子用户实战，改为系统性内部测试。Day 17+ 系列任务
- **做法**：按 CLAUDE.md V1.1 第十五节"内部测试方案"6 个核心要点逐项执行：
  1. **5 条核心链路 × 双视角**：LA（张三）和 BA（李红）各走一遍完整流程
  2. **状态机边界矩阵**：每个状态下的"能"与"不能"逐项验证
  3. **防伪视角隔离**：必须用 curl 直打接口验证脱敏（不能只在 App 看页面），验证 LA 查 transaction 时 `ba_deal_*` 字段为 null
  4. **模拟难缠用户**：含找家人测试 30 分钟，模拟极端操作和边界场景
  5. **数据一致性**：工作台 6 个数字 vs 各 Tab 列表数字一一核对
  6. **健壮性 / 边界数据**：空数据、超长文本、非法输入等边界条件
  7. **历史数据回归**：Day 10-16 已修 bug 的旧数据仍能正常展示
- **产出**：测试清单写入 `docs/test_plan_v1.md`，发现 bug 当场修

### 🔴 任务 1：历史"无 customer_id"协作回填脚本
- **背景**：Day 12 之前的协作里 customer 是手填，没进 `customers` 集合。**内部测试前必做**，否则客户选择器看不到老协作的客户
- **做法**：写一次性脚本扫历史 `showing_requests` 里 `customer_id=null` 的条目，按 `ba_agent_id + customer_surname + customer_gender` 归并到客户档案
- **纪律**：必须先 dry-run，磊看过输出 OK 后再 `--apply` 真改（Day 15 铁律）
- **风险**：低，纯数据操作，脚本会自动备份到 `showing_requests_backup_day15`

### 🔴 任务 2：B 对象存储（COS）迁移
- **背景**：照片 base64 存 MongoDB 是 50 户内的临时方案，种子用户产生真实数据后必须迁
- **前置**：磊需要先申请好腾讯/阿里/七牛 COS 账号
- **做法**：前端改图片上传走 COS SDK / 后端签名直传，老数据迁移
- **风险**：中，涉及文件读写链路变更，迁移后需双视角验证

### 🟡 任务 3：房源表单缺奖金输入字段
- **背景**：listing_create_screen.dart / listing_edit_screen.dart 没有奖金输入入口（Day 8 暴露，V8.1 没修）
- **做法**：前端表单加 TextField + 后端 UpdateRequest 补字段（坑 1：Pydantic 三处必改）
- **风险**：低

### 🟡 任务 4：成交日期 vs 带看时间严格比较 bug
- **背景**：同天带看同天成交被拦（Day 8 暴露）
- **做法**：检查 `transactions.py` 里日期比较逻辑，确保用日期粒度而非时间戳
- **风险**：低

### 🟡 任务 5：`initiate_transaction` 未给 `bonus_yuan` 拍快照
- **背景**：V10 金额锁定时点 = BA 提交时，但当前实现不是严格快照（Day 8 暴露）
- **做法**：在 `initiate_transaction` 中对 `bonus_yuan` 拍快照，后续 LA 确认优先读快照
- **风险**：中，涉及金额逻辑

### 🟡 任务 6：带客申请 7 天过期定时任务
- **背景**：APScheduler 每天 03:00 扫 `pending` 状态的申请标记 `expired`，不依赖推送
- **做法**：在 `scheduler.py` 中新增定时任务
- **风险**：低，45 分钟工作量

### 🟡 任务 7：共享库卡片奖金标签复检
- **背景**：V8.2 标注此条"可能已无效"——`_format_listing_anonymous_lite` 已返 `bonus_yuan`，前端卡片左上角已显示橙色"奖¥xxx"
- **做法**：真机共享库页面看一眼，确认已显示即关闭此条
- **风险**：极低，30 分钟验证

### 🟢 任务 8：状态码命名风格不统一
- **背景**：`pending_confirm`（带看）vs `pending_la_confirm`（成交）前缀不一致（Day 16 发现）
- **做法**：**保留现状不动**（改后端要回填历史），仅在 CLAUDE.md 立新规：新建状态机一律遵循 `<actor>_<action>` 命名
- **风险**：无，纯文档

### 🟢 任务 9：dashboard_summary 被单次会话重复请求
- **背景**：V7.2 已记，工作台 summary 接口在单次会话中被多次调用
- **做法**：排查前端 FutureBuilder / 路由守卫，减少重复请求
- **风险**：低

### 🟢 任务 10：状态码零散硬编码英文 → 逐个修
- **背景**：V8.2 标注"真出现一处修一处即可"
- **做法**：真机使用时发现英文状态码就改用 `status_labels.dart`
- **风险**：极低

### 🟣 任务 11-13：迁移相关
- 任务 11：上 git 远程版本管理（Github/Gitee）
- 任务 12：前端 baseUrl 做 dotenv 配置（换 WiFi 不用手动改）
- 任务 13：生产 MongoDB 迁云（需先申请云 MongoDB）
